# PartyUp v1.1 独立交互原型

> THROWAWAY PROTOTYPE。演示数据，未连接真实服务、设备或媒体。
> 用于比较界面结构与操作路径，不是可分发的正式 PartyUp 客户端。

## 运行

本机 Windows 调试桥 Worker 已启动时，从仓库根运行一条命令：

```bash
scripts/wdb.sh build-run --project docs/design/prototype/PartyUp.UiPrototype.csproj \
  --exclude third_party --exclude .cache --exclude .tools --exclude .design \
  --exclude artifacts --exclude .docs --exclude .research-tmp
```

桥会在 Windows 本机磁盘快照构建并启动独立窗口。停止时使用提交返回的任务 ID：

```bash
scripts/wdb.sh stop <任务ID>
```

不要使用正式客户端的启动入口，不需要启动 PartyUp 服务端或编译媒体 DLL。本项目不引用正式客户端程序集，不请求真实登录、不采集音视频、不配置启动项、不注册全局键或托盘、不保存账号/设置。

如果 Worker 没运行，先按仓库[调试桥说明](../../../tools/windows-debug-bridge/README.md)启动 Windows Worker。不要把 UNC 运行或 WSL 软件渲染的结果当成 Windows 本地盘效果与性能证据。

## 要回答的问题

- A 频道通话时浏览 B 的文字，能否一眼分清当前浏览与通话归属？
- 手动观看、聊天侧栏、全屏以及停止动作是否容易发现？
- 通话、发布、观看、文字草稿与设置是否可以独立表达，而不互相误伤？
- 深浅主题、窄窗口和放大文字是否仍可操作？

方案 A 为频道轨+主区+底部通话条，B 为顶部频道导航，C 为通话舞台优先。通过原型的方案选择器比较结构，不能把换色当成布局比较。

## 建议点击顺序

1. 使用任意明确为演示用途的账号字段进入原型；空提交和注册邀请码分支用于看错误与忙碌态，不是真实鉴权。
2. 加入“开黑大厅”，再浏览“攻略与杂谈”；检查通话留在前者，两边草稿独立。
3. 在通话频道发布演示共享，浏览另一频道后尝试转移；分别走取消与模拟失败，检查失败后未加入、返回原频道不自动加入、共享不自动重开。
4. 从当前通话频道选一路观看，再切另一路、展开文字侧栏、主窗内全屏、退出全屏和停止观看。
5. 使用独立演示工具注入发送失败、断线、目标结束和设备拔出；确认状态清楚且不会宣称真实操作成功。
6. 打开设置，切深色/浅色/跟随系统及文字大小；其他系统设置只演示，不执行系统操作。
7. 在 900×600 和 1280×800 窗口检查折叠、焦点及关键媒体控制是否可达。

## 证据边界

项目构建成功不代表上述路径已通过。具体构建、截图与点击结果由主代理另行记录；没有记录的项目保持“未验证”。真实鉴权、采集/播放、停止网络接收、设备热切换、全局 PTT、托盘、开机启动、媒体恢复和四档真实 DPI 都不由演示状态证明。

状态数据默认仅保存在内存。Inspector 用于查看模拟状态，不能把其中的通话、画面、连接等字段当成真实网络结果。

本原型在 `prototype/v1.1-ui` 分支。最终方向尚待用户视觉验收；不得直接将原型代码提升为正式实现。
