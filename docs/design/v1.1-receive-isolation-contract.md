# B2 接收传输隔离实施合同

2026-11-06，Lead审查后放行。对应[缺口台账](<v1.1-backend-gaps.md>)MED-02/03；仍由唯一显式DeepSeek写入角色实施，不改UI，不引入通用MediaSession框架。

## 不能沿用的方案

直接调用现有ReleaseStreamObjects会关闭同时持有本端发送轨的pc_，清source_/track_/video_sender_/sharing_，因此不能作为停看实现。仅给新sink贴target/epoch也无法鉴别同SSRC、同传输中迟到的旧RTP。换槽或重发旧PC上的offer不构成新的隔离身份。

## 有限interface与所有权

1. 发布与接收各自拥有生命周期。接收module外部只需open/signal/close及当前帧；一个viewer恰好一路，不扩多路解码。可用独立receive-only PC，或由窄module独占一个现有native engine，选择真实代码里最小的实现；不强制为了类名增加层次。
2. 每次成功的严格观看都持有新receive session：channel、认证viewer/连接、target、server generation、不可混淆的session/nonce、实际transport。identity在信令与媒体进入接收器之前建立。
3. unwatch只销毁当前接收传输/slot/sink；成功ACK代表接收侧关闭完成，server撤转发/通知对应发送侧关闭该viewer的发送传输。不得关闭本端发布/voice、重启采集源或把发布状态改为停止。
4. direct必须保持既有1v1上限，由server裁决transport与容量；与该viewer有关的发送侧停止是对应会话控制，不能全局screen.stop。
5. relay为每个严格watch提供真实新的接收传输身份，和本端上传PC分离。不得用现有混合上传/下载VideoRoom.Refresh直接重建整个成员PC；旧会话的RTP/信令/回调不能进入新会话。

## 协议/兼容/时序

- 新能力显式opt-in、server/native/对端能力探测；旧字段/导出/结构保持。允许最小加法ABI，但不预设必须新增三个导出；复用成熟JSON/SDP库，不手写SDP parser。
- legacy/v1未opt-in继续原路径；旧server/DLL或对端无法满足严格合同，明确报不支持，不偷偷降成sink-only成功。
- media.signal的from由服务端认证赋值，session/generation须与当前连接所持接收lease匹配，不能让客户端任意声称身份。过期offer/answer/ICE按会话拒绝。
- watch与close先后顺序、offer先到/ACK先到、取消/重连/Dispose/跨连接、并发watch→stop的本地代次需明确。过期ACK不得重新arm已停止的接收会话。
- 严格撤租必须显式按真实连接owner及receive/session ID精确匹配，和legacy sharer_id目标守卫分开；禁止把receiveId传进sharerId字段或用null无条件清新选台。本地exactly-once关闭不能代替远端幂等撤租，迟到ACK即使本地已关闭仍须准确清理其远端会话，不能误清同目标的新session。
- SFU锁内只改状态，避免在hub锁内等PC关闭/回调；按session归属清理，不连带清同成员另一连接的发布或观看。

## 回归门槛

先锁住可变红的真实路径，再实现：
- 自身发布+观看时停看/重看，发布继续出帧、采集源未停/未重建；voice状态/会话不变。没有安全合成音频seam时标记语音实际帧未验，不可开真实麦克风代替。
- A→B→A与Refresh使用新接收传输；延迟/重放旧会话UDP/RTP或旧offer，证明它不增加新会话交付帧且不显示旧nonce。仅手工调用旧FrameAccepted回调不能算RTP回归。
- 停看后网络RTP计数在合理在途清空窗口后停止；非媒体ICE/DTLS保活与RTP分开计数。direct发送方收到关闭会话后不继续增长该会话RTP，relay撤转发同理。
- 第一观看的两个到达顺序、无选台不收、切源失败/取消不串流、重看、旧端兼容、错误身份/代次拒绝、并发关闭与断线清理。
- 继续通过Go全量test/vet/server+SFU race、RunWatch、RunAudioSwitch与客户端编译。所有实际命令/退出码/未验项回报Lead；Go由Lead原命令审批执行，不更换缓存路径绕过权限。

## 批次边界与红回归判据（执行中复核）

- 可先交B2a relay隔离这一条完整垂直切片；direct带receive_id若明确NOT_IMPLEMENTED，只能算B2b仍开放，不能作为本合同全部完成或擅自降成legacy/pause-only成功。后续direct同样必须满足新接收传输/停收/保发布与voice。
- 新导出未实现导致编译/链接失败只是interface构建红，不是行为red。需要旧实现可交付旧会话帧、停看误伤本端发布或旧会话RTP/帧计数增长的实际反例，再证明修复后消失。
- 未做UDP/SRTP旧包延迟/重放或等效真实包回归时，RTP级隔离继续标未验；不以新PC的静态形状、旧callback丢弃或编译通过充数。

只运行synthetic/fake回归，不采桌面/不开真实音频。硬件、真实NAT与正式UI E2E继续独立标记未验。任何必要的大接口变化先停并回报，不以隐藏画面、延时丢帧或随机epoch替代真实传输隔离。
