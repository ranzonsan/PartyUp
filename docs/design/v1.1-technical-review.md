# PartyUp v1.1 技术边界核查

日期：2026-11-04。
状态：两项只读核查及主代理关键证据复核完成；Q18–Q20 有限扩展与剩余产品行为已获批准；具体 interface 设计与依赖验证未完成，未实现、未构建、未运行 GUI。
需求来源：[UI 设计简报](v1.1-ui-brief.md)。

## 1. 核查方式与结论

两项独立核查分别通过 `console-opendesign/deepseek-v4.1-flash` 与 `console-opendesign-2/deepseek-v4.1-flash` 完成。主代理复读了关键客户端、服务端及媒体核心代码，以下结论不等价于运行验证。

**结论：视觉与大部分桌面交互可在客户端实施；真实的按需观看以及完整音频设备设置需要越过原先默认保护的协议、服务端或原生媒体 interface。**

不能用隐藏 Image 冒充停止接收，不能用另一套独立采集栈冒充控制当前通话设备，也不能把按住说话降级成切换式静音后宣称需求已完成。

## 2. 已确认的代码事实

### 浏览频道与通话目前耦合

[MainViewModel.OpenChannelAsync](../../client/ViewModels/MainViewModel.cs#L474-L528) 切换频道会先销毁旧 ShareSession、复位语音状态、退订旧频道，再订阅新频道并创建 ShareSession。

[ShareSession.DisposeAsync](../../client/Services/ShareSession.cs#L1173-L1195) 当前包含 VoiceLeave、解绑事件和取消后台队列，但不应将其当成已完成全部屏幕发布、网络连接与引擎资源清理的统一退出入口。

[服务端 unsubscribe](../../server/internal/server/hub.go#L250-L264) 会离开旧频道语音。要实现浏览 B 而通话保留 A，客户端必须保留 A 的必要订阅和会话所有权，不能沿用当前切换路径直接销毁会话。

### 视频目前是订阅后提前协商、自动绑定共享

[视频房间入口](../../server/internal/server/voice.go#L610-L629) 在频道订阅时接入 relay 视频房间。

[VideoRoom.Join](../../server/internal/sfu/video_room.go#L117-L189) 创建上传 transceiver 和观看槽位，offer 发出后把已有共享绑定给新成员。[bind/unbind](../../server/internal/sfu/video_room.go#L412-L441) 已有 ReplaceTrack 与解除绑定的内部实现，但没有等价的用户级“只看所选一路”控制契约。

这描述现有频道内媒体分发行为，不据此宣称发生了越权访问。谁能观看属于产品权限决策，不能由技术审计擅自收紧或扩张。

### 原生观看接口仍是桩，取帧不区分共享者

[pu_screen_watch / pu_screen_unwatch](../../src/media-core/src/media_engine.cpp#L4084-L4095) 直接返回 PU_NOT_IMPLEMENTED。

[AcquireFrame](../../src/media-core/src/media_engine.cpp#L3140-L3174) 只接受空流名或 `remote`，输出的 stream_id 恒为 1。[AttachVideoSink](../../src/media-core/src/media_engine.cpp#L1106-L1117) 将视频轨接入同一个 remote sink，未给 UI 提供稳定的“这一帧属于所选共享者”契约。

因此，需要真正的目标选择、停止接收、清除旧帧和防止旧回调串流语义。但这**不自动要求实现多路同时解码或通用多流框架**：本轮一次观看一路，优先比较“服务端只转发所选一路 + 明确的目标与代次”方案。最终 interface 形状待技术规格决定。

### 音频设备能力未暴露给客户端

[pu_voice_params](../../src/media-core/include/partyup_media.h#L329-L335) 只有结构尺寸、频道、模式与标志，没有音频设备参数。[托管导出清单](../../client/Services/MediaEngine.cs#L71-L113) 没有设备枚举/选择、本端麦克风电平及设备变更相关能力。

[VoiceJoin](../../src/media-core/src/media_engine.cpp#L3890-L3911) 当前会跳过名称包含 NVIDIA/Broadcast 的设备，并尝试选择其他录音设备。这与明确尊重用户选择、跟随系统默认的目标不一致；新设计不能继续用设备名称启发式替代真实选择。

[静音与闭音](../../src/media-core/src/media_engine.cpp#L3963-L3999) 调用 ADM 的 SetMicrophoneMute / SetSpeakerMute，线程投递已有约定。仅凭这些调用不能确认其对系统其他应用、硬件静音及设备隐私指示的全部影响，更不能未经验证宣称可直接安全承载所有 PTT 行为。

### 现有窗口退出不等于完整会话退出

[MainWindow 的关闭处理](../../client/MainWindow.axaml.cs#L73) 仅停媒体泵；[StopMediaPump](../../client/ViewModels/MainViewModel.cs#L221-L226) 仅释放 pump。托盘常驻、退出登录和真正退出必须形成显式且可测试的资源所有权与关闭流程。

## 3. 有限实施范围（Q18 已批准范围，具体 interface 待设计）

### 客户端 module

将浏览频道状态与通话 module 的生命周期分离。UI 通过小 interface 发起加入、离开、观看、停止和配置操作，复杂的订阅保持、恢复、并发与错误归属集中在 implementation 内。

测试与真实 UI 经过同一 seam；原型数据使用独立 adapter，不在设计器构造真实媒体引擎。不要只把大 ViewModel 的每个方法搬进一层同样庞大的转发 interface。

托盘、启动、全局键和设置存储可在客户端接入成熟依赖或明确的平台能力，但依赖、许可、版本兼容与失败行为尚未验证，不在本报告锁定具体库。

### 服务端与协议

增加明确的观看目标与停止请求、结果及状态；区分文字订阅与视频接收意图。relay 只向 viewer 绑定所选共享，停止后解除媒体转发，不必为了停止观看销毁语音会话或自己的屏幕发布。

支持显式清理发布、观看与成员状态，验证取消、断线、转移及退出不会留下陈旧成员或共享记录。现有退订路径的共享清理风险尚未复现，不标记为已确认运行缺陷。

direct 路径也须满足目标选择与停止语义，不允许只完成 relay 然后把两种模式一起标为完成。服务端仍是 direct/relay 策略的唯一裁决源。

### 原生媒体 interface

实现现有 watch/unwatch 意图及可靠的目标归属，按需补充最小扩展。为输入/输出选择、本端电平及热插拔恢复提供通话实际使用的同一音频栈能力。

优先加法式导出与能力探测，保护既有结构布局；是否保持 ABI 版本必须通过旧新客户端/DLL组合及布局检查证明，不能仅因“加函数”就直接承诺兼容。旧 DLL 不具备新能力时明确提示，不假装设置生效。

### 测试与生命周期

设备测试不能偷偷加入语音或向远端发布测试内容；PTT、静音与闭音的组合要有统一有效状态，系统锁定、挂钩失败、重连及退出不得导致持续开麦。

媒体引擎初始化发生在启动阶段，不等于已证明启动即采集；是否占用麦克风及何时开始/停止实际采集需真机观察与对端测试。

## 4. 不采纳为既定结论的子代理建议

- 不用切换式热键替代已批准的真正按住说话。全局键实现应核查按下/释放、冲突、权限、隐私与游戏兼容性；原型或接入验证前不承诺适配所有游戏/反作弊环境。
- 不把现有 ADM 静音直接命名为“只影响本应用的数字静音”，也不默认它会停止采集；需先验证实际语义。
- 不为一次看一路的需求自动扩建多路渲染框架；仅建立选中目标与帧归属所需的最小可靠契约。
- 不把代码里的 native mode 常量等同于最终媒体路径。现行 direct/relay 策略仍由服务端控制，不能因此报告 relay 未实现。
- 不把设备初始化、陈旧共享清理风险等静态推断写成已复现 bug。
- 不采用子代理提出的首帧低于 2 秒、重看低于 500 毫秒等未经测量与用户确认的固定性能门槛。

## 5. Q18–Q20 用户裁定（2026-11-04）

1. 批准为落实既定观看与音频设置所需的有限协议、服务端与原生媒体扩展，不扩大为媒体架构重写或新增产品方向。仍先验收设计原型，再正式实现。
2. 仅观看当前通话频道的共享；浏览其他文字频道不改变观看目标，未加入通话不自动接收画面。不引入独立于通话的跨频道观看。
3. 显式转移通话失败后明确落在“未加入通话”，提供返回原频道的显式操作，不自动反复跳转。原共享停止后必须手动重开。

以上批准的是范围与行为，不是具体函数签名、依赖版本、兼容性或实现通过。本阶段仅有静态核查与设计文档，未改应用代码、未测试依赖、未运行媒体或 GUI。后续交互原型须明确模拟状态，不冒充真实媒体能力。
