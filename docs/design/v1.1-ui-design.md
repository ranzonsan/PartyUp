# PartyUp v1.1 界面与交互原型设计稿

日期：2026-11-04。
状态：设计准备稿，供下一阶段原型实现使用；不是截图、不是可运行原型，也不是已通过用户视觉验收的最终设计。
基线：[Q1–Q20 设计简报](v1.1-ui-brief.md)；[技术核查及扩展授权](v1.1-technical-review.md)。

## 1. 设计方向

频道轨 + 任务主区 + 独立通话条。

频道导航只表达正在浏览哪里；主区表达正在读消息、观看共享或调整设置；通话条始终清楚表达正在和谁通话、麦克风与扬声器的有效状态。不能再把日常媒体控制与成员列表、共享配置、诊断日志挤在同一滚动区域。

这是桌面通讯产品，不采用营销网页的巨型标题、装饰卡片、霓虹或玻璃特效。继续使用既有 Avalonia 基础，布局与语义资源集中定义；实际控件与依赖在原型接入时核实。

本稿中的色值、尺寸、布局位置是设计提案，用户已批准的是目标和行为，不把这些具体数值冒充已批准的视觉结果。

## 2. 品牌与视觉资源

已读取[现有图标](../../brand/v2/icon.svg#L1)、[标志源](../../brand/v2/icon-mark.svg#L1)与[字标源](../../brand/v2/splash.svg#L18-L24)，并查看[当前安装画面](../../assets/splash.png)。品牌事实为：背景黑 `#0B0C0E`、奶白 `#F4F1EA`、信号橙 `#FF5A2B`，字标源声明 Noto Sans。保留 Logo，不重新绘制标志或自造图标集。

设计采用橙色作为唯一品牌强调色，成功、警告、错误仍有各自功能色并配合文字或图标。现有蓝色按钮不作为新视觉的主方向。

| 语义 | 深色提案 | 浅色提案 |
| --- | --- | --- |
| 窗口/导航底 | `#0B0C0E` | `#F5F2EC` |
| 主内容底 | `#111216` | `#FBF9F4` |
| 浮层/输入底 | `#181A1F` | `#FFFFFF` |
| 正文 | `#F4F1EA` | `#141517` |
| 次要说明 | `#A9ADB5` | `#565A61` |
| 品牌填充 | `#FF5A2B` | `#FF5A2B` |

| 观看舞台底 | `#07080A` | `#0B0C0E` |

浅色舞台保留深底属于媒体 letterbox，不是整块界面反转为深色。浅色品牌文字需独立选深橙，不能直接以亮橙小字落在浅底上。

以上不是已测对比度结果。原型需检查正文、辅助文本、焦点、按钮与错误状态的对比度，不能仅验证表里的基础色。

Windows 正文先验证系统 UI 字体与中文回退，品牌字标保持原样。不把系统字体是否覆盖中文当作既成事实，也不因未经实测的字体体积估算排除必要依赖。

初始字阶建议：正文 14、控件 13–14、辅助文本 12、区标题 18，行距优先保证中文阅读。文字大小设置增大时允许重排，不靠截断或缩字维持原布局。间距使用 4 的基数；圆角主要为 4/6/8，对话框可为 10；原型验证后定稿。

## 3. 壳层与区域归属

```text
原生窗口框架
┌────────────┬────────────────────────┬─────────────┐
│ 服务器名称 │ 当前浏览/观看上下文     │ 成员或共享  │
│ 统一频道表 │ 聊天或观看任务主区     │ 按需展开    │
│            │                        │             │
│ 自己/设置  │ 消息输入或观看操作     │             │
├────────────┴────────────────────────┴─────────────┤
│ 通话归属与状态   共享 / 麦克风 / 扬声器 / 离开     │
└──────────────────────────────────────────────────┘
```

这是结构草图，不是视觉截图。频道保持统一列表，每个频道仍有文字、语音和共享；不擅自新增“文字频道”“语音频道”两种产品类型。

登录后，底部通话区有“未加入”“加入中”“通话中”“重连中”“离开中”“转移失败”等状态，而不是没有通话就整个消失。未加入时提供明确的加入入口，转移失败时保留失败与恢复操作。登录界面不显示无意义的通话工具栏。

浏览频道与通话频道不同的时候，通过主区标题和底部通话归属共同表达；不额外堆两条重复横幅。共享列表必须标明属于当前通话频道，不能让浏览 B 的成员列表和通话 A 的共享列表混淆归属。

## 4. 四类主界面

### 登录

居中单列表单，约 360 逻辑像素宽，保留品牌标志与字标。地址、用户名、密码均有独立标签。注册为明确模式入口，进入后出现邀请码；不添加记住密码、自动登录或服务器切换。

校验错误就近显示，连接错误单独归属；忙碌态防止重复提交，但允许理解当前进度。关于和版本入口不使用虚构发布版本。原型不发真实登录请求，输入只保留在内存，使用演示账号文案。

### 聊天

主区优先消息阅读、草稿和发送。成员可在右侧查看，共享列表单独分组并显示通话频道名。没有当前通话时，明确提示加入后可观看，不能仅放一个无解释的灰色按钮。

正在浏览 B、通话在 A 时，浏览标题为 B、通话条为 A。显式“加入 B 的语音”才触发转移。不能将普通导航做成自动挂断、自动观看或权限变化。

失败消息原文与重试入口就近显示；读旧消息时不强制滚底。原型可用按钮注入发送失败、收到新消息和断线状态，不伪造真实服务器回执。

### 观看

舞台占主位，标题明确“通话频道 A / 共享者 / 共享来源”。提供选中目标切换、全屏、停止观看；聊天侧栏可展开。

观看 A 时浏览 B，只改变文字浏览上下文，不自动改变或停止观看 A。聊天侧栏标题必须明确当前文字对象，不能显示 B 却把输入发到 A。即使侧栏收起，当前观看目标和通话归属仍可见。

以“停止观看并返回聊天”作为明确的结束动作，原型不提供一个会悄悄继续收流的含糊返回按钮。进入设置等临时任务时，须保持清楚的观看状态和返回入口，不把临时查看设置伪装成媒体已经停止。

主窗内全屏不另开观看窗口。保留退出全屏入口与 Escape 路径；麦克风、扬声器、离开、停止观看仍必须可达，不能只在鼠标悬停时才能发现关键安全操作。

### 设置

分组为：外观、音频、快捷键、窗口与启动、关于与诊断；账号及退出登录入口明确可见。不引入空页面或未批准功能。

设置页为行式布局，标签、当前值、说明与错误各有归属，不做每一行一张卡片。进入设置不结束当前通话；返回保留此前任务上下文。

设备、电平、播放测试、全局快捷键、启动项和托盘在原型中一律注明模拟。原型不访问真实设备、不监听全局键、不改启动项、不注册托盘、不保存凭据。正式实现缺能力时明确提示，不假装配置已生效。

## 5. 小窗口与缩放

主要设计窗口为 1280×800，最小验收窗口仍为已批准的 900×600，不擅自降到 960×540 或其他高度。

提案：宽窗以频道栏约 232、次要信息栏约 288、观看聊天栏约 320 为起点；中等宽度优先收起次要信息；接近最小宽度时频道和次要面板改按需展开，不缩小正文字体硬塞。不要同时在窄窗固定频道栏、成员栏、设置导航和聊天侧栏。

展开抽屉不允许遮住通话区和关闭抽屉入口；设置长内容可滚动。可调整区域的具体 splitter、最小尺寸及断点需在原型中验证，不把纸面相加等同于实际可用。

100/125/150/200% 是真实显示缩放验收，不是截图缩放。若某块物理屏幕在该缩放下容不下最小逻辑窗口，应记录环境限制并换用足够工作区验证，不能悄悄改写最小尺寸或宣称已经通过。

## 6. 首轮原型范围与证据

四类界面深浅两套，共八个主状态。关键变体至少包括：浏览 B 而通话 A、共享中转移确认/取消/失败、未加入、无共享、等待首帧、目标结束、断线与恢复、最小窗口。

视觉原型先比较三种结构，而非三次换色：A 为本稿推荐的频道轨+主区+底部通话条；B 为紧凑顶部频道导航+主区+底部通话条；C 为通话舞台优先、文字侧栏的布局。三者保持同一品牌与全部已批准行为，不能为了区别方案而删掉核心控制。四类界面的完整验收以选定方向为主，另两种提供足以比较信息层级的主状态。

这是原生桌面项目，没有现有网页路由；原型用独立 Avalonia 入口及明确的原生方案切换器，不为模仿 Web 的 URL 参数引入浏览器壳。实际应用的 ViewModel 构造会触达媒体引擎，独立演示 adapter 可避免误启动真实采集。原型应隔离在 main 之外的 prototype 分支，用户选定方向后仅将已验证决策带回正式实现。

原型顶部或独立检查区注明“交互原型 / 演示数据 / 未连接服务器”，完整展示影响决策的模拟状态；不能只在源码注释里说明。设备测试不显示会被误认为真实硬件读数的未标注数值。

状态模型至少分开：登录状态、浏览频道、通话状态及频道、发布状态、观看目标、显示布局、设置面板、连接状态、分频道草稿。仅用一个 selectedChannel 或一个 layout 枚举不足以表达这些互不等价的归属。

正式协议、媒体采集、真正停收、系统音频设备、全局 PTT、托盘及开机启动、真实 DPI 与中文输入法仍需后续独立验证。原型状态转移正确不等于这些能力已经完成。

## 7. 主代理对协作者提案的审查修正

以下不进入设计基线：

- 将统一频道拆成文字频道/语音频道两组产品类型。
- 在观看中浏览文字频道就强制结束观看，或自动切到另一频道共享。
- 通话条仅通话时出现，导致未加入、转移失败时缺少明确控制入口。
- 根据 1080p@200% 的工作区推算，将最小验收高度从 600 改为 540。
- 使用未经验证的字体体积或固定对比度数字作已完成的优化/无障碍证据。
- 以“避免引库”为原则排除必要控件或依赖；仍按能力、维护、许可和兼容性选择。
- 将上面结构草图、模拟设备数据或静态状态说明当成已经完成的视觉/原生功能验收。

本阶段前置决策已收束；下一阶段据此实现独立原型并进行实际视觉检查，而不是继续用文档替代可看、可操作的设计。

## 8. 交互审查后的最小点击清单

以下全部尚未执行。只有实际点通并保存对应证据后，才能标为原型设计行为通过；不能写成功能通过。

| 路径 | 必须观察到的结果 |
| --- | --- |
| 登录与主题 | 空提交/无效邀请码就近报错，登录忙态防重入；演示登录后深浅主题均完整可用 |
| 浏览与草稿 | 加入 A 后浏览 B，通话仍是 A；A/B 草稿独立，发送失败保留原文，重试不静默丢失 |
| 发布状态 | 选源、准备中、发布中、失败和停止可区分，全部明确是演示状态，不访问真实采集 |
| 手动观看 | 看 A 的一路时可读 B；切换先清旧画面并等新首帧；全屏可键盘退出，停止后回到 B 聊天 |
| 转移与失败 | 共享中转移有确认，取消保持原状；失败清除旧通话/发布/观看状态；返回 A 只浏览，重新加入和重开共享均为显式操作 |
| 断线与安全退出 | 草稿可写，网络发送和新媒体操作禁用；本地静音、停止、离开和退出等降低暴露的操作仍可达，不等待网络恢复 |
| 设置与任务保持 | 查看设置不结束现有通话；关闭回此前聊天或观看；设备/全局键/启动等始终标模拟，不产生系统效果或虚假成功提示 |
| 最小窗口 | 900×600 下重复浏览、观看、转移失败及退出路径；抽屉可关闭、不遮关键通话控制、焦点可见 |

断线“暂停媒体操作”在原型中解释为暂停新发起的网络/媒体动作，不阻止用户本地静音、停止或退出。自动重连与用户显式结束的意图需分开：用户已经离开或退出后，不得恢复旧通话或共享。

转移失败会退出旧观看与全屏，清理旧帧，显示未加入及原因；“返回原频道”仅恢复浏览，不暗中重入通话。该恢复路径必须与普通断线后的自动恢复场景分开演示。
