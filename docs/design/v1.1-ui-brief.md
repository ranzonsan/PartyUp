# PartyUp v1.1 客户端 UI 设计简报

状态：Q1–Q20 产品与有限跨层扩展基线已确认；技术边界已静态核查；进入设计准备，尚未完成交互原型或获得正式实现批准。
技术核查：[技术边界核查报告](v1.1-technical-review.md)。
日期：2026-11-04。
来源：本阶段用户对 Q1–Q20 的逐轮裁定。

本文件是 v1.1 新界面的需求基线，不代表功能已实现、界面已出图或验收已通过。技术核查可能暴露需另行批准的协议、服务端或媒体接口扩展；不得用静态原型掩盖这些缺口。

## 1. 目标与范围

主场景：语音常驻，偶尔打字和共享屏幕，服务小圈子日常开黑。

四项体验目标全部保留，不以其中一项替代其他项：

1. 操作顺手、入口清楚。
2. 聊天、语音、共享不相互挤占。
3. 消除骨架与调试工具感，形成完整产品体验。
4. 文字易读，状态与错误清楚。

界面布局、操作流程、视觉与 UI 层结构可全面重做。保留现有产品能力；新增能力必须逐项批准。下文明确标注已批准的能力属于本轮范围。

默认保护现有 HTTP/WS 协议、媒体核心、服务端传输策略与打包运行边界；这不是对所有新需求都能纯 UI 实现的承诺。若必须越过边界，先提交最小变更方案与影响，再取得批准。

## 3. 信息架构与通话归属

必须区分两种用户意图：

- 浏览频道：决定文字消息、草稿与当前阅读位置。
- 通话频道：决定当前语音和共享会话的归属。

这里的名称是 UI 设计用语，不新建服务端频道类型。频道仍承载文字、语音和共享。

点击频道仅浏览文字，不隐式加入、离开或转移通话。界面清楚显示当前通话频道，并提供返回该频道的入口。

显式点击“加入语音”才转移通话；同一时刻仅加入一个语音频道。正在共享时，转移前明确提示会停止当前共享，用户取消则保留原状态。转移失败后明确落到“未加入通话”，提供返回原频道的显式操作，不自动反复跳转；原共享须手动重开。具体失败分类、清理完成语义及返回操作在技术规格中定义，不假定服务器支持原子切换。

核心语音控制始终可达：加入/离开、麦克风静音、关闭扬声器及其当前状态。不能只改变说明文字而让按钮仍像未切换。

## 4. 观看与共享

### 聊天布局

文字阅读和输入占主位；共享列表提供清楚的观看入口。新的共享出现不自动抢占用户当前布局。

### 观看布局

用户从当前通话频道的共享列表选择一路观看，可切换目标或停止观看。同一时刻只观看一路。仅观看当前通话频道的共享，未加入通话不自动接收画面；浏览其他文字频道不切换当前观看目标，观看区明确标注所属通话频道。

共享画面占主区域；聊天侧栏可展开；语音控制保持可用。用户可返回聊天布局。

支持主窗口内全屏观看，退出后恢复原布局。不做独立观看窗口，不承诺多路同时观看。

“停止观看”必须在技术规格中定义真实媒体订阅与资源行为，不能只隐藏画面然后宣称停止接收。不同共享者之间的切换必须核查流标识、协商和原生取帧接口。

发布共享保留源选择、开始与停止等现有能力。共享来源、发布中、等待首帧、观看中、失败和结束应有可区分的 UI 状态。

## 5. 文字与异常体验

- 每个频道保留本次运行内的输入草稿，不默认扩展为跨重启保存。
- 发送失败保留原文并提供重试；不能清空后仅显示错误。
- 读旧消息时不强制滚到底，显示新消息提示及回到最新的入口。
- 断线时可继续写草稿，暂停发送和媒体操作；恢复后不自动发送草稿。
- 连接状态常驻；操作错误就近显示，避免共享错误覆盖语音错误等错误归属混淆。
- 保留已有自动重连与媒体恢复能力；恢复过程及结果可理解。
- 空频道、无消息、无成员、无共享、加载中、无可用采集源、媒体引擎缺失均需设计，不用空白区域或日志替代。
- 发送重试的消息去重与不确定结果必须在技术规格中定义，不能未经验证承诺恰好一次投递。

## 6. 设置与桌面行为

### 外观

支持深色、浅色及跟随系统，提供文字大小调节。浅色独立设计与验收，不能简单反色。

### 音频

麦克风和扬声器分别选择，并支持跟随系统默认。提供麦克风电平与扬声器测试。

指定设备拔出时显示提示并回退默认设备，不能静默失声。实现不得绕过用户静音、闭音或按住说话状态；设备测试与实际发布音频的隔离必须纳入技术规格。

### 快捷键

支持配置全局麦克风静音、关闭扬声器、按住说话和显示主窗口。默认自由说话，全局快捷键默认不绑定，避免抢占游戏按键；冲突明确提示。

按住说话的按下/释放、失焦、系统锁定及退出时的安全释放需验证。不得仅用窗口内键盘事件冒充全局快捷键。

### 托盘、退出与启动

关闭按钮默认收至托盘并保持通话，首次明确提示。用户可改为关闭即退出。托盘提供显示主窗及明确退出入口。

退出登录必须真正结束旧身份的连接与媒体活动并返回登录界面，不是只切换可见视图。

开机启动默认关闭；开启后可选择静默进入托盘，不自动加入语音或开始共享。未批准凭据保存，不得借开机启动默认引入保存密码或自动登录。

### 关于与诊断

提供关于与版本信息。诊断和路径历史按需展开，而不是占据日常主界面。

保留语音与屏幕共享各自的当前传输路径、变更时间和原因，特别是自动回落原因。路径由服务端裁决，客户端不提供 direct/relay 切换开关。

设置持久化范围、默认值、失败提示及存储依赖在技术规格阶段明确。用户批准设置能力，不代表具体存储方案已选定。

## 7. 视觉与适配要求

克制、现代、桌面原生感，保留适度开黑氛围；信息紧凑但不拥挤。不做霓虹电竞、重玻璃特效、满屏卡片或营销页式排版。沿用现有品牌，不重做 Logo。

以 1280×800 为主要设计尺寸，最小支持 900×600。逻辑尺寸与物理像素须在实际 Avalonia 原型中区分，不能把 200% 缩放等同于把布局尺寸减半后截图。

验收 100%、125%、150%、200% 显示缩放。窄窗口折叠次要侧栏，不靠缩小字体硬塞；语音控制始终可达。

四类主界面：登录、聊天、观看、设置。每类均需深浅主题设计及关键状态。跟随系统需验证系统主题变更的实际行为。

## 8. 工程约束

- 沿用 .NET/Avalonia 现有技术栈；依赖按能力与兼容性选择，不追求最小化依赖。
- 不以自造轮子或其他变通方式绕过依赖。
- 成熟文件格式使用第三方库解析，或避免解析；禁止手写字符串/字节流 parser。
- 禁止程序化修改代码，包括 heredoc、Python、sed、Perl 等；代码改动仅用直接文件编辑工具。
- 保护媒体事件泵、帧获取/释放、信令串行与重连生命周期；不能将事件驱动上屏随意改成 UI 定时器轮询。
- 全局快捷键、设备与托盘、启动功能优先采用成熟组件或明确的官方平台 API；兼容性与许可须有证据。
- 子代理与团队其他智能体仅使用 DeepSeek，派发时核对模型路由。
- 主代理负责统筹、重大决策建议及最终验收；委派任务需明确读写范围和依赖。

## 9. 不随本轮自动纳入

服务器切换与凭据保存、摄像头、移动端、会议功能、E2EE、逐成员混合传输、成员中继、自动更新、CI/Docker，以及多路同时观看与独立观看窗口。

已有 v1 功能与限制要保留并如实表述，不能把服务端支持两路发布直接写成客户端已支持两路同时观看。

## 10. 设计与实现关卡

1. 当前关卡：已批准需求汇总，核查关键能力的技术边界。
2. 技术关卡：列明现成能力、必要扩展、依赖候选、生命周期与测试要求。越过既定边界需用户裁定。
3. 设计关卡：登录、聊天、观看、设置的深浅主题设计与关键交互原型，由用户确认。
4. 实现关卡：设计确认后，按可验收的垂直切片拆分任务；不得凭本简报自行开始全面实现。
5. 最终关卡：独立审查、真实 Windows GUI、真实媒体与恢复行为验收。静态原型、编译通过、无头自检均不等价于最终通过。

## 12. 技术核查与后续验证

已完成静态核查，证据、主代理复核及未采纳建议见[技术边界核查报告](v1.1-technical-review.md)。真实按需观看涉及服务端订阅与原生 interface；音频设备配置和本端电平也缺少现有原生能力，不能仅改布局实现。

后续仍需定义和验证：

- 浏览频道与通话频道解耦后的订阅、成员与媒体所有权模型。
- 单路观看的目标归属、真正停止接收与切换共享者所需的最小扩展。
- 设备枚举、热切换、电平和播放测试的线程、作用域与真实设备行为。
- 全局键/PTT、托盘、启动和设置持久化的依赖、许可、兼容性及 Windows 运行约束。
- 退出、注销、窗口隐藏、重连和通话转移时的统一资源清理与错误恢复。

这些是实现方应调查验证的事实，不要求用户猜测代码能力。用户已在 Q18–Q20 批准有限跨层扩展、仅当前通话频道观看，以及转移失败落到未加入状态；后续只提交超出这些边界的真正新增取舍。

## 13. 原型与最终验收的证据要求

以下是验收方案，不是本轮已运行结果。

### 原型验收

- 主画面至少覆盖登录、聊天、观看、设置各自的深浅两种主题，共八个主状态；错误、空态、忙碌与断线可作为同一界面的变体，不要求每种组合都另做一张静态图。
- 必须演示浏览与通话频道不同、共享中转移确认与取消、手动观看与返回聊天、窄窗口侧栏折叠、设置与退出的操作路径。
- 原型使用合成数据并明确标记，不能让静态电平、虚构帧率或预置连接状态冒充真实媒体功能。
- 精确色值、字体、间距、图标和动效尚未定稿，在设计关卡形成统一资源与组件规范。

### 最终功能验收

- 第二端收到文字：检查真正的第二端消息和显示结果，不能用发送端回显证明接收成功。
- 浏览不打断通话：明确记录浏览频道与通话频道不同，确认同伴仍可双向交流，且未因普通导航重建媒体会话。
- 观看选择与停止：发布两路可辨识画面，逐次选择一路；停止后核对目标接收/解码活动确实停止。若协议或原生接口暂不能支持，则该条不能标通过。
- 共享画面在动：用可辨识的动态测试源核对目标媒体区域和接收端帧进展，不能仅凭整窗截图哈希差或收到第一帧证明持续显示正常。
- 音频设备和PTT：以实际目标设备与对端听音确认路由和开闭；计数器非零只是辅助证据，不能证明指定扬声器有声或静音未泄露。
- 断线与恢复：分别验证断开、恢复、界面状态、通话归属、媒体恢复和草稿不自动发送；服务端重启、网络故障注入和物理断网是不同场景，记录实际执行的那种。
- 生命周期：托盘隐藏保持通话；退出登录或明确退出后不残留旧身份连接、采集或媒体会话；不能只依赖强杀进程清理来证明退出正确。
- 所有必要断言失败均应导致失败结果；跳过、超时、未知、未运行不得归类为通过。证据必须对应当前构建与同一次测试运行。

### 回归与责任边界

既有无头自检、服务端测试及打包检查仍有价值，但不能覆盖视觉树、焦点、主题与实际上屏。最终报告分开列出静态审查、构建、无头、真实GUI和真实媒体结果。

主代理审阅最终差异、证据与未通过项，再给出验收结论；协作者完成任务或脚本返回零，不自动等于整版通过。任何跨协议/服务端/ABI的扩大变更，均回到技术关卡先批准。
